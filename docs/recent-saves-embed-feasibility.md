# Click-to-load YouTube embeds: feasibility

**Conditionally viable; not implemented in PR #12.** Keep the current thumbnail until an explicit “Load player” action, create only one iframe, and remove it on replacement/page/filter changes. This preserves zero player startup work while browsing. A loaded player still costs network/memory. With `autoplay=0`, loading and pressing Play are separate user actions. [YouTube supports a plain iframe and this parameter](https://developers.google.com/youtube/player_parameters).

The current manifest has no custom CSP, frame-src restriction, or embed-related permission change. A basic cross-origin YouTube iframe appears compatible with the [default extension CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy); this is an architectural inference, not an installed-extension playback test. Keep all parent-page code packaged locally rather than loading the remote IFrame API script into the extension page. Reader credentials and messages must stay outside the player. No CSP, security setting, permission or header-rewriting changes are proposed.

The main unresolved constraint is client identification. [YouTube requires a Referer or supported equivalent](https://developers.google.com/youtube/terms/required-minimum-functionality#api-client-identity-and-credentials), and [error 153 indicates missing identification](https://developers.google.com/youtube/iframe_api_reference#onError). An extension-origin page must be tested in a separate extension profile: a successful localhost embed would not prove this works. If the installed extension cannot identify itself under existing permissions, retain Open on YouTube rather than adding header permissions, relaxing CSP, or inventing a referrer.

Some owners disallow embedding; unavailable/private videos need the same fallback. YouTube requires at least a 200×200 player and recommends 480×270 for 16:9: very narrow cards need a fallback or taller player. These [size requirements](https://developers.google.com/youtube/player_parameters#Overview) limit an unchanged 16:9 thumbnail replacement at small widths.

Recommendation: keep thumbnails in this draft, then validate the one-player, no-autoplay approach in an isolated extension profile before deciding on a separate embed change. No embed or live-player test was added here.
