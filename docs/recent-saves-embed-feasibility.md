# Click-to-load trial and validation limits

PR #12 now includes a bounded trial. Thumbnails remain until an explicit pointer/keyboard activation creates one player iframe per Recent saves page. Loading another video removes the old frame. Close returns focus to the matching thumbnail; pages/filters, card removal/reordering, hiding/pagehide and undersized layouts unload it. Nothing restores a player automatically. Metadata refreshes preserve the same frame instead of reparenting it and restarting its requests.

The URL uses the canonical video ID and `autoplay=0&playsinline=1`. Loading the player and pressing Play are separate actions. Frames require at least 200×200 usable pixels; smaller cards keep the thumbnail and Open on YouTube link. These choices follow [YouTube's iframe, autoplay and size guidance](https://developers.google.com/youtube/player_parameters). There is no remote IFrame API script in the extension page, no frame message bridge, and no Reader credentials in the player. No identification is fabricated: the browser's normal `strict-origin-when-cross-origin` referrer policy is used. Production extension permissions and CSP are unchanged.

**Live extension-origin playback is unverified.** The available tool surfaces expose only the in-app browser and MCP Apps, without an isolated extension-loading capability. Mock native iframe/focus/lifecycle tests passed, but those cannot establish live playback. A frame opening/loading is not reported as playback success.

[YouTube requires Referer/client identification](https://developers.google.com/youtube/terms/required-minimum-functionality#api-client-identity-and-credentials); [error 153 indicates missing identification](https://developers.google.com/youtube/iframe_api_reference#onError). Some owners also disallow embedding. A cross-origin frame's load event cannot reliably detect these errors. The explicit Open on YouTube fallback is therefore always present; no header rewriting, invented origin/referrer, permission additions or security relaxation is used to bypass a failure.

201 Node regressions pass, including five player lifecycle cases. Native checks used a visibly labelled synthetic frame served only on loopback; the offline fixture allows only that same-origin frame, blocks remote connections, and has no real Reader credentials. See [recorded checks](watch-list-native-checks.md). Manual playback from the existing extension remains the next validation step; keep the fallback if the account/video/client-identification path is unsupported.
